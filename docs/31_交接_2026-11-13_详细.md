# 31 交接（详细）：camellia iOS 触控可用状态与性能问题

日期：2026-11-13
设备：Redmi Note 10 5G（camellia / MT6833 / Dimensity 700），iOS 16.7.16 (20H392)，UFS 根盘
当前状态：**触控已可用**（能点开设置、看到“关于本机”），但系统明显卡顿；下一步先解决性能。

---

## 1. 一句话结论

物理触摸从“完全不可用”做到了“可用”：GPIO bit-bang SPI → 下载 NT36672C 固件到 SRAM →
10ms 轮询 65 字节报文 → 解析 10 指 → `sweet_hid_touch()` → SpringBoard 正常响应。
当前卡顿的根因是 **单核（cpus=1）+ 无 GPU + present 每帧只回拷 200 行 + daemon 崩溃循环**，
不是触控本身。

## 2. 硬件事实（已核实）

| 项 | 值 |
|---|---|
| SoC | MT6833（Dimensity 700），ARM64 |
| 触摸 IC | Novatek NT36672C，PID=5949，fw=18，18×36 通道 |
| 面板 | 1080×2400（物理），iOS 呈现 1125×2436 |
| SPI | SPI4 @ `0x11018000`；MI=GPIO12，MO=13，CLK=97，CS=98（功能 2） |
| 复位 | GPIO15（novatek,reset-gpio=<&pio 15 0>） |
| 中断 | GPIO14/EINT14（active low） |
| GPIO 块 | `0x10005000`（0x1000） |
| Pad 块 | iocfg_lm `0x11E20000`（pin14）；iocfg_bl `0x11E60000`（pin12） |
| 事件页 | **0x22D00**（trim `0c 00 00 72 66 03` → NT36675 map） |
| hw_crc | 2（长度写 3 字节，CRC 4 字节） |
| PMIC | MT6360（vtp = LDO2，1.2–3.6V），iOS 侧无驱动 |
| 电源/音量键 | 走 PMIC/SPMI，当前无驱动 → 不可用 |

MTK Paris GPIO 寄存器模型（**这是 0216 修复的关键**）：

```
group = (pin/32)*0x10
mode  = 0x300 + (pin/8)*0x10，字段 (pin%8)*4
dir   = 0x000+group（读），0x004+group（置输出），0x008+group（置输入）
dout  = 0x100+group（读），0x104+group（置高），0x108+group（置低）
din   = 0x200+group
```

bit-bang 采样顺序（cannon 验证）：设 MOSI → 延时 → **在上升沿前采样 MISO** →
CLK 高 → 延时 → CLK 低。窗口命令后 1 个 dummy 字节，数据从第 3 个时钟起。

## 3. 触控软件架构

```
sweet_touch_mtk.c (bsd/dev)
├─ GPIO/bit-bang: pin_mode/dir/out/in, spi_cs/spi_xfer
├─ Novatek 协议: nvt_set_page / nvt_read / nvt_read_latched / nvt_write
├─ 固件: fw_decode(hex) → fw_parse(ILM/DLM/Info/Overlay) → nvt_boot_fw()
│        （bootloader reset → 写 SRAM → 描述符/CRC → boot ready → 轮询状态）
├─ 校验: FWINFO(0x22D78) / PID(0x22D9A)
└─ touch_hid_loop(): 10ms 轮询 0x22D00 的 65 字节 → touch_hid_frame() → sweet_hid_touch()

SweetHID.cpp (iokit/Kernel/arm/hid)
└─ SweetHIDTouch::touch(finger, down, x, y)：生成 IOHID digitizer collection + 10 个 finger child
```

- 坐标范围：`x 0..1079`、`y 0..2399`；边缘 48px 内会置 `kIOHIDDigitizerEventFromEdgeTip`（解锁手势必需）。
- 报文格式：10 指 × 6 字节；`id=p[0]>>3`，`state=p[0]&7`（1=按下，2=移动）；
  `x=(p1<<4)|(p3>>4)`，`y=(p2<<4)|(p3&0xF)`。
- 空闲/恢复包：前 6 字节为 `0x77/0xFD/0xFE` → 视为无触摸，释放所有手指。
- 手指索引：`id-1`（0..9）。

## 5. 固件：来源、提取、格式

### 5.1 来源

（Android sparse，9.1 GB）→ `vendor_a` ext4 → `firmware/nt36672c_tm_01_ts_fw.bin`。

### 5.2 提取命令

```powershell
python -X utf8 tools/unpack_super.py raw super.img D:\super_camellia.raw
python -X utf8 tools/unpack_super.py parts D:\super_camellia.raw
python -X utf8 tools/unpack_super.py extract D:\super_camellia.raw vendor_a D:\vendor_camellia.img
& 'C:\Program Files\7-Zip\7z.exe' x D:\vendor_camellia.img -oD:\nvt_fw 'firmware\nt36672c_tm_01_ts_fw.bin' -y
```

说明：super.img 的 LP geometry 在 **0x1000**，metadata 在 **0x3000**（不是 0/0x1000）；
`vendor_a` extent 在 sector 458752；7-Zip 可直接读 ext4。

### 5.3 固件信息

| 项 | 值 |
|---|---|
| 文件 | `nt36672c_tm_01_ts_fw.bin` |
| 大小 | 139,264 B |
| SHA256 | `B7756699088AA5A5E31B9DF1F93D0A0147F3F003AA9E87F691875922503CE481` |
| 头 | `u32@0 = 0x100`（header 结束） |
| 结束标志 | `"NVT"` @ `0x1FFFD` |
| 元数据 | `12 ED 12 24 38 04 60 09` @ `0x19F30`（fw18、18×36、1080×2400，小端） |
| 分节 | ILM src 0x100/sram 0/size 0x12577；DLM 0x180D0/0x27110/0x43B7；Info-12 0xFF；Overlay-0/1 在 DLM src 处 |

### 5.4 固件启动序列（`nvt_boot_fw`）

```
1. fw_decode() 解 hex → fw_parse() 解析 17 个分节
2. （可选）reset 脉冲：GPIO15 低 10ms → 高 10ms    [sweetmtkrst=1]
3. 写 0x3F0FE = 0x69（进 bootloader），delay 5ms
4. 写 0x3F310 = 0（关 fast read）
5. 读 0x1F64E 6 字节旧 trim（应为 0c 00 00 72 66 03）
6. 每节写 SRAM：64B 一块、不跨 128B 页；写 size+1 字节
7. 写 ILM/DLM 描述符 0x3F128/0x3F12C（3B）、长度 0x3F118/0x3F130（3B）、
   CRC 0x3F100/0x3F104（4B）
8. （可选）0x3F30E 置 bit7（BLD CRC）、0x22D50=0xAE（FW CRC）  [sweetmtkcrc=1]
9. 0x22D60=0（清 reset）、0x3F10D=1（boot ready）
10. 轮询 0x22D60 到 0xA0..0xAF（最多 1s）
11. 读 0x22D78 FWINFO（期望 12 ed 12 24 0438 0960）
12. 读 0x22D9A PID（期望 5949）
```

失败返回码：-1 NVT 标志；-2 解码/解析；-3 旧 trim；-4 reset 超时；-5 FWINFO 不对。
`fw=结果/阶段` 阶段值：1 解析、2 bootloader、3 写完、4 CRC、5 reset、6 FWINFO、7 PID。

## 10. 日志诊断手册

### 10.1 探针模式（`sweettouchhid=0`）

```
SWEET TOUCH MTK: pass N trim 0c0000726603 irq=0 rst=xx host=xx hs=xx
  page=22d00 pid=5949 fw=0/7 info 12ed1224 0438 0960 rep 0a105cd2 ... nz=..
```

- `fw=0/7` = 固件成功；
- `info` 必须是 `12ed1224 0438 0960`；
- `pid=5949`；
- `rep` 前 6 字节全 `77` = 空闲。

### 10.2 HID 模式

```
SWEET TOUCH HID: polling page 22d00 every 10 ms
SWEET TOUCH HID: down finger=0 at 269,1474
SWEET HID: touch 0 down at 269,1474
```

### 10.3 常见故障

| 现象 | 原因/处理 |
|---|---|
| 无任何 `SWEET TOUCH` 行 | 内核没带上补丁；用 `strings` 验证 |
| `fw=-1` | 解码前查了 NVT 标志（0220） |
| `fw=-2` | hex 解码/头解析失败 |
| `fw=-3` | 旧 trim 不对；查 reset 脉冲/SPI |
| `fw=-4` | reset state 不到 A0..AF；查 CRC/写 SRAM |
| `fw=-5` | FWINFO 校验失败 |
| 坐标全 0/对不上 | 读了 0x21C00（0224 修复） |
| 全部 `77` | 未触摸/固件恢复；先看 pid |
| 触摸 down/up 抖动 | 空闲包误判或 SPI 读错；降速/重试 |

## 11. 性能：根因与优化路径

### 根因（按影响）

1. **单核**：loader 阶段 PSCI `CPU_ON` 挂住，一直 `cpus=1`；XNU 平台层目前**没有** SMP/PSCI 实现。
2. **无 GPU**：全部 CPU 软件合成 1080×2400。
3. **present 窗口**：200 行/帧 → 全屏刷新约 5fps；300 行反而更卡（161 实测）。
4. **daemon 崩溃循环**：identityservices/configd 等持续重启。

### 已验证的调参

| 配置 | 结果 |
|---|---|
| 窗口 200 / 250kHz | 162，可用但卡 |
| 窗口 300 / 500kHz | 161，更卡（CPU 不够） |

### 下一步（按性价比）

1. **触摸自检+自动重试 / HID 心跳（1–2 小时）**：先消掉“时好时坏”的不确定性
   （见 11.5），否则性能调参没有意义；
2. **SMP 可行性探测（约 1 小时）**：平台层调 `PSCI_VERSION` / `CPU_ON` 并打日志；
   通了再谈 2→4→8 核（3–7 天）；不通则需 spin-table/ATF（1–2 周起）。
2. **降逻辑分辨率（@2x，0227 计划）**：iOS 按 750×1624（375×812 @2x）渲染，
   present 时最近邻放大到 1080×2400；渲染像素从 274 万降到 122 万（约 2.2 倍）。
   同时改 `SweetHID.cpp` 的归一化（`x * fLogicalW / 1080`）。
   **基线问题**：CI 的 `darwin-xnu-build` pin 只有构建脚本，没有源码；
   源码 = Apple xnu + 上游 0001–0081 + 本地 0082–0226。本地 `payload/out/lftree10_new`
   是最接近打完补丁的版本，用它作基线写补丁，并加一行唯一标记（如
   `SWEET FB: logical 750x1624 scaled`）在构建后用 `strings` 验证补丁是否真的生效；
   若被 build.sh 静默跳过，就换 `lftree10` / `lftree9_new` 重试。
3. **present 改整帧 + NEON**，目标 30fps。
4. 关动态效果/透明，排查 daemon 崩溃。
5. GPU 驱动（工程最大，最后）。

## 11.5 开机差异：为什么“时好时坏”

实机观察：同一张 162 镜像，有时能用，重启后又卡到滑不动。不是纯运气，而是三个不确定性叠加：

1. **daemon 崩溃循环**
   `identityservices`、`configd` 等每次开机崩几次、何时崩是随机的；崩溃重启会短时吃掉大量 CPU，
   表现为“刚才还好，重启后突然滑不动”。
2. **触摸固件每次启动的成功率**
   每次开机都要重新下载固件；reset 脉冲/SPI 时序只要有一次不干净，IC 可能进恢复态
   （报文全 `0x77`）。这时不是卡，而是**怎么滑都没反应**。
3. **没有 CPU 调频/温控/PMIC 驱动**
   CPU 跑在 LK 留下的频率上，没有 DVFS、温控降频、电压管理；
   不同开机状态的频率/负载可能不同。

**区分方法**：
- 画面还在动、只是慢 → daemon/CPU 负载问题；
- 画面完全静止、怎么滑都没反应 → 触摸那一轮没起来（固件恢复态或 HID 线程没跑）。

**把“运气”变成可观测（下一步优先做）**：
1. **触摸自检 + 自动重试**：开机读 FWINFO/PID，不对就自动重下固件一次（最多 2 次）；
2. **HID 心跳**：每 5 秒打一行 `alive frames=... events=...`（控制台可见版本），
   滑不动时一眼区分“触摸死”还是“系统卡死”；
3. 记录每次开机的 fw 结果/PID，统计失败率。

### 11.6 控制台回归（2026-11-14 实测）

- **159**（xnu227，`sweetnopresent=1`、HID 关）：控制台日志正常，能滚屏；
- **163c / 165c**（xnu230，同样 `sweetnopresent=1`）：黑屏 → 苹果标，无控制台日志；
- **163**（xnu230，UI 呈现 + `sweetfb_noconsole=1`）：能进桌面，触摸正常。

结论：不是日志被关，而是 **xnu230 + `sweetnopresent=1` 这个组合**出现了回归；
日常使用以 163（UI 版）为准。要抓日志，可用 recovery 的 `sweet-log-pull.sh`
（`sweetlog=1` 写 userdata 尾部，`fastboot boot recovery` 后 adb 读取，不写分区）。

## 12. 已验证 / 未验证

**已验证**
- 触摸点击、打开 App（设置→关于本机）；
- 固件下载、PID/FWINFO、10 指解析、HID 注入；
- 直读探针、reset 脉冲、SRAM 回写校验；

**未验证/不可用**
- 多指手势（缩放/旋转）实际体验；
- 息屏/唤醒、音量键、充电状态（无 PMIC 驱动）；
- 长期稳定性（daemon 崩溃、内存压力）；

## 14. 从零复现（简要）

1. 取原厂 ROM 的 `super.img`，用 `unpack_super.py` 拆 `vendor_a`，7-Zip 取固件；
2. 生成 hex 头 `sweet_nvt_fw_hex.h`（脚本见 evidence 记录）；
3. 应用 0212–0225 补丁，CI 构建内核；
4. `mk_device_boot.py` 打 162 同款 cmdline 的启动图；
5. `fastboot flash boot` 刷入 `boot_a`；
6. 验证 `fw=0/7`、`pid=5949`、`info 12ed1224 0438 0960`；
7. 点屏幕测试。

## 15. 红线与注意

- 只写 `boot_a`；不要刷 userdata/dtbo/super/modem/persist；
- 不要用 `sweetlog=1`（会写 userdata 尾部）；
- cmdline 关键参数放前面，长度 < 512；
- 每次构建后 `strings` 验证补丁真的生效（build.sh 会静默跳过失败补丁）；
- SMP/PMIC 实验版单独编号，永远保留 162 作为可回退基线。

## 16. 术语

- **ILM/DLM**：Novatek 固件的指令/数据 SRAM 段；
- **FWINFO**：固件自报的版本/通道/坐标范围（事件页 +0x78）；
- **trim**：芯片 ID（bootloader 下 0x3F004）；
- **bootloader reset**：写 `0x3F0FE=0x69` 让 IC 进入下载模式；
- **present window**：每个 vsync 从渲染 surface 回拷到面板 framebuffer 的行数。
