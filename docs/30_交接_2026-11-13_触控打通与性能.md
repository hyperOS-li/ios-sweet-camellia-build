# 2026-11-13 交班：M5 触控打通 + 性能瓶颈分析

## 一、今天完成了什么

**M5 触控从零到可用**：160 版刷入后，可以点开「设置 → 关于本机」，真实触点已经进入 SpringBoard。
这是这台 camellia（MT6833 / iOS 16.7.16）第一次有可用的物理触摸。

完整链路（补丁 0212–0225，均在 `xnu/patches/`）：

1. **GPIO/SPI 层**（0216）：用 YukinoXNU-Cannon 的 MTK Paris GPIO 模型
   （mode `0x300+(pin/8)*0x10`；DIR/DOUT 用 set/clear 别名；DIN `0x200`），
   bit-bang 在**上升沿前**采样；trim 读到 `0c 00 00 72 66 03` → NT36675 map，
   事件页 **0x22D00**，hw_crc=2。
2. **固件下载**（0217/0218/0220/0221/0222）：
   - 芯片平时停在 bootloader，必须下载固件才有触摸；
   - 固件从本机 V12.5.9.0 `super.img` 提取（`tools/unpack_super.py`）：
     `vendor/firmware/nt36672c_tm_01_ts_fw.bin`，139,264 B，
     SHA256 `B7756699088AA5A5E31B9DF1F93D0A0147F3F003AA9E87F691875922503CE481`；
   - 流程：`0x3F0FE=0x69` 进 bootloader → reset 脚低10ms/高10ms →
     写 ILM/DLM/Info/Overlay → 描述符/长度/CRC →（默认跳过 CRC）→
     `0x22D60=0`、`0x3F10D=1` → 轮询 reset state → 读 FWINFO/PID。
3. **HID 注入**（0223/0224）：10ms 轮询 65 字节报文，10×6 字节解析，
   `sweet_hid_touch()`；**必须读 0x22D00**（0224 修复了读 0x21C00 导致坐标全错的 bug）。
4. **性能优化**（0225）：HID 只选一次页、连续读；周期日志降到每 1000 帧。

## 二、为什么现在这么卡（根因，按影响排序）

1. **单核运行（最大原因）**
   本移植从 loader 阶段就因 PSCI `CPU_ON` 不返回而用 **`cpus=1` 单核**启动
   （见 `03_实验记录.md`、`06_交班_HANDOFF.md`）。
   现在 XNU 的异常向量/中断早已建立，**可以尝试让 XNU 自己拉起其余 7 核**：
   加 `cpus=8`（或 `cpus=4`）boot-arg 试启动，成功后 CPU 能力直接 4–8 倍。
2. **无 GPU 加速**
   Apple GPU 驱动不存在，SpringBoard/UIKit 全部走 CPU 软件合成；
   1080×2400 的每一帧都是 CPU 画的。
3. **present 回拷窗口**
   SweetFramebuffer 每个 vsync 只回拷 `sweetpresentwindow` 行（当前 200），
   整屏 2400 行要 12 帧 → 全屏刷新约 **5fps**，所以滑动像幻灯片。
   窗口调到 300 反而更卡（161 已验证），说明瓶颈是 CPU 总量，不是拷贝策略。
4. **daemon 崩溃循环**
   `identityservices`、`configd` 等反复崩溃（"Too many corpses"），持续吃 CPU。

## 三、下一步建议（按性价比）

1. **先试 SMP**：`cpus=8` / `cpus=4` 启动，看是否稳定；这是唯一能数量级改善的方向。
   - 若 panic：查 PSCI CPU_ON 的返回、GIC redistributor、secondary 入口；
   - 若成功：先跑 4 核稳，再上 8 核。
2. **降逻辑分辨率**：让 iOS 以 750×1334（或 828×1792）渲染，present 时放大到 1080×2400；
   像素量降到约 1/3，CPU 合成压力大幅下降。
3. **present 改整帧 + NEON**：放弃 200 行窗口，改成每帧整帧 memcpy/缩放（NEON），
   目标 30fps；CPU 富余后再谈 60fps。
4. **减少特效/崩溃**：关动态效果、透明度；排查 configd/identityservices 崩溃原因。
5. GPU 驱动：工程量最大，最后做。

## 五、当前状态与注意事项

- 手机当前刷的是 **162**（触控可用、偏卡）；
- **同一镜像时好时坏**：daemon 崩溃循环、触摸固件每次下载成功率、无 CPU 调频/温控驱动
  三个不确定性叠加；详见 `31_交接_2026-11-13_详细.md` 第 11.5 节；
- 下一步优先做“触摸自检+自动重试、HID 心跳”，把“运气”变成可观测，再谈性能；
- 只写 `boot_a`，不要动 userdata/dtbo/super/modem/persist；
- 物理电源/音量键仍不可用（`sweet_keys.c` 是 Qualcomm 方案，MT6833 需要 MT6360/MT6359 PMIC 驱动）；
- 息屏/唤醒、充电状态都依赖同一个 PMIC 驱动，后续可参考 cannon 的 `power/mt6375.c` + `spmi/pmif.c`。
