# 2026-11-13 触控打通：从 bootloader 到真实 HID 触摸

## 结论

**触摸已可用**：160 版刷入后，用户可点开「设置 → 关于本机」，说明真实触点已经进入 SpringBoard。
当前剩余问题是**性能（卡顿）**，不是功能。

## 关键链路

1. **GPIO/SPI**（0216）：采用 YukinoXNU-Cannon 的 MTK Paris GPIO 模型
   （mode 0x300+(pin/8)*0x10；DIR/DOUT 用 set/clear 别名；DIN 0x200），
   bit-bang 在**上升沿之前**采样 MISO；trim 读到 `0c 00 00 72 66 03`，
   命中 NT36675 map（事件页 **0x22D00**，hw_crc=2）。
2. **芯片原本停在 bootloader**（147/148 的 FWINFO 是垃圾）：厂商驱动每次开机
   写 `0x3F0FE=0x69` 进 bootloader，再下载 `nt36672c_tm_01_ts_fw.bin` 到 SRAM。
3. **固件提取**（`tools/unpack_super.py`）：本机 V12.5.9.0 `super.img`（sparse 9.1GB）
   → LP metadata（geometry@0x1000，metadata@0x3000）→ `vendor_a` ext4 →
   `firmware/nt36672c_tm_01_ts_fw.bin`（139,264 B，
   SHA256 `B7756699088AA5A5E31B9DF1F93D0A0147F3F003AA9E87F691875922503CE481`）。
4. **RAM boot**（0217/0218/0220/0221/0222）：hex 固件内嵌内核；先 `fw_decode()` 再查
   `NVT` 标志；默认开启；reset 脚低 10ms→高 10ms；写 ILM/DLM/Info/Overlay →
   描述符/长度/CRC →（默认跳过 BLD/FW CRC）→ `0x22D60=0`、`0x3F10D=1` →
   轮询 reset state → 读 `0x22D78` FWINFO（`12 ed 12 24 0438 0960`）与
   `0x22D9A` PID（`5949`）。
5. **HID 注入**（0223/0224）：每 10ms 读 65 字节报文，10×6 字节解析
   （id=p[0]>>3，state 1/2 为按下，x=(p1<<4)|(p3>>4)，y=(p2<<4)|(p3&0xF)），
   全 0x77/0xFD/0xFE 视为空闲并释放；调用 `sweet_hid_touch()`。
   **注意：必须读 0x22D00，不能读探针候选 0x21C00**（0224 修复的正是这个 bug，
   它导致坐标永远对不上）。

## 性能

- 无 GPU，CPU 合成；`sweetpresentwindow=200` 时整屏刷新 ≈5fps，明显卡；
- 161（0225）优化：HID 只选一次页、之后连续读；SPI 500kHz（`sweetmtkdelay=1`）；
  present 窗口 300 行（≈8fps）；周期日志降到每 1000 帧。
- 进一步可做：present 窗口/频率调参、HID 轮询 15–20ms、减少 SweetHID 事件对象分配。
