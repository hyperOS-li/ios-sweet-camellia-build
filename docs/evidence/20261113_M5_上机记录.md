## 2. 144d（0213 探针，延迟 300 s）→ 内核 panic

- 能正常开机，控制台常驻（`sweetnopresent=1` 本身没问题）；
- 约探针启动后出现 panic：

```
Error!! Current Magic 0xff000000, expected value 0x46554e4b
panic ... Kernel data abort, at pc 0xfffffe00074f2060
 x9: 0x000000011e60090   (PAD_IES_MI 的物理地址)
```

**根因**：`0213` 里 `PAD_*` 宏写成了完整物理地址（`0x11E60090` 等），而 `pad_bit()`
在 `st.bl = ml_io_map(0x11E60000)` 的映射基址上又加了一次，实际访问 `0x11E60000 + 0x11E60090`
（未映射）→ kernel data abort。144（delay=5）是探针一启动就踩；144d 是 5 分钟后踩。

修复（0215）：pad 宏改成相对基址的 `0x90/0xB0/0xD0`（iocfg_bl）和 `0x50/0x60/0x80`（iocfg_lm），
并加两项诊断：

- pad 写之前打印 `mmio gpio/lm/bl` 映射地址；
- SPI **mode 0 / mode 3 自动切换**（厂商 `spi->mode` 未知，trim id 不合法时换模式重读），
  pass 行里打印 `mode=`。
